Project request — build a complete, production-ready web application (frontend + backend) that provides free file conversion services for students and office workers. The app must be anonymous (no user registration) and must use a REST API.

High-level summary:
- Purpose: free web tools: (1) PDF ⇄ DOCX conversion, (2) PDF compression (reduce file size).
- No user accounts or signups. Anonymous uploads only.
- Frontend deployed on Vercel. Backend deployed on a VPS (Docker).
- Use REST API for all backend endpoints.

Requested tech stack:
- Frontend: Next.js (React) + TailwindCSS. Should be optimized for Vercel deployment.
- Backend: Python + FastAPI, containerized with Docker and orchestrated with docker-compose. Use FastAPI for REST endpoints.
- Conversion engine: LibreOffice headless (inside the backend Docker container) for PDF ⇄ DOCX conversions. Use a reliable PDF compression tool (e.g., GhostScript) for compression.
- Storage: local filesystem on the VPS for temporary files (with a cleanup policy). Provide instructions to switch to S3 later.

Functional requirements:
1. Frontend pages & UX:
   - Home page with clear UI for two tools:
     - Tool A: Convert file (drag & drop + browse), choose target format: `docx` or `pdf`.
     - Tool B: Compress PDF (upload PDF, choose quality/ratio preset: high/medium/low).
   - Show upload progress, conversion progress, and download button when ready.
   - Show warnings for unsupported file types and file size limits.
   - Simple Privacy / Terms page describing that files are removed after 60 minutes (configurable).
   - Responsive and mobile-friendly design.

2. Backend API (REST):
   - POST `/api/convert`:
     - Accept `multipart/form-data` with fields: `file` and `target_format` (`docx` or `pdf`).
     - Return JSON with `job_id`, `status` (processing), and optionally estimated time.
   - POST `/api/compress`:
     - Accept `multipart/form-data` with `file` (PDF) and `preset` (`high`/`medium`/`low`).
     - Return JSON with `job_id` and `status`.
   - GET `/api/status/{job_id}`:
     - Return current status, progress percentage if available, and download URL when done.
   - GET `/download/{file_id}`:
     - Serve the converted/compressed file via a temporary signed token URL or short-lived token (prevent hotlinking).
   - GET `/health`:
     - Basic health check endpoint.
   - Optional admin-only endpoint `/api/admin/stats`:
     - Return aggregated metrics (count of conversions last 24h, current queue length). Protect via a simple env-secret token (not user-facing).

3. Behavior & processing:
   - On upload, backend saves input file to a safe temp folder, creates a `job_id`, returns processing status immediately, then processes the file asynchronously.
   - Use LibreOffice headless to convert PDF ↔ DOCX:
     - Example command: `libreoffice --headless --convert-to docx /app/uploads/input.pdf --outdir /app/out`
   - Use GhostScript (or equivalent) to compress PDFs: provide commands for common presets.
   - Ensure robust error handling: return meaningful error messages for unsupported formats, conversion failures, or corrupted PDFs.
   - Files must be removed automatically after a configurable TTL (default 60 minutes). Implement a cleanup background task or cron-like worker in the container.

4. Security & limits:
   - Maximum file size default: **50 MB** (configurable via env var).
   - Rate limiting by IP (configurable); return 429 when exceeded.
   - Validate file MIME types and extension; sanitize filenames.
   - Enable CORS only for the frontend domain(s) (configurable).
   - Prevent path traversal and ensure uploads cannot execute code.
   - Optionally integrate a CAPTCHA checkbox on the frontend to reduce abuse (must remain optional and not require registration).
   - Signed download tokens/short-lived URLs to avoid direct hotlinking.

5. Devops & deployment:
   - Provide `Dockerfile` and `docker-compose.yml` for backend including LibreOffice and GhostScript installation. Ensure conversions work inside the image.
   - Frontend ready for Vercel (including examples of environment variables).
   - Provide GitHub Actions workflow templates:
     - Frontend: build and auto-deploy to Vercel.
     - Backend: build Docker image and either push to Docker Hub or perform SSH deploy to a VPS (document both options).
   - Provide a detailed `README.md` with step-by-step deploy instructions:
     - How to create and configure a VPS (install Docker & docker-compose).
     - Set required environment variables.
     - How to run locally (`docker-compose up`) and how to deploy.
   - Provide `.env.example` with all environment variables listed and explained:
     - `MAX_FILE_SIZE`, `FILE_TTL_MINUTES`, `RATE_LIMIT_PER_MINUTE`, `FRONTEND_ORIGIN`, `ADMIN_SECRET_TOKEN`, `STORAGE_PATH`, etc.

6. Tests & quality:
   - Include unit tests for backend endpoints (pytest) and an integration/e2e smoke test that simulates upload → convert → download.
   - Provide clear inline comments in the code explaining the conversion call, job flow, cleanup, and security checks.
   - Provide logging for errors and job lifecycle for troubleshooting.

7. Deliverables (repository structure):
   - Root README with project overview and deploy steps.
   - `frontend/` — Next.js app ready for Vercel.
   - `backend/` — FastAPI app with Dockerfile, docker-compose, background worker for cleanup, and tests.
   - `.github/workflows/` — CI/CD examples.
   - `.env.example`, `LICENSE`, `CONTRIBUTING.md`.

8. UX / other non-functional requirements:
   - Keep the frontend UI minimal and very easy to use for students.
   - Show clear instructions and explain privacy: files auto-deleted, no account collection, usage limits displayed.
   - Make it easy to add more tools later (e.g., merge PDFs, split PDF).

9. Extras (nice-to-have):
   - Polling approach for job status (recommended) and optional WebSocket demo for real-time progress if detected.
   - Admin small UI path (protected by a secret) to view recent jobs and force cleanup.
   - Docker healthchecks and restart policies in docker-compose.

Please produce a complete codebase ready to commit and deploy, with clear documentation and all files. Keep the app anonymous (no login). Use clean, idiomatic code and provide helpful comments in English.

If anything in the above is unclear, choose sensible defaults and proceed (do not wait for clarification). Thank you.
